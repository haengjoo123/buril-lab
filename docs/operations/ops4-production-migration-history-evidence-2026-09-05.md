## 적용 중 발견한 검증기 결함과 조치

첫 적용은 기준선 1개 상태까지 끝났지만, 사후 증거를 만들 때 PowerShell이 단일
원격 이력을 배열이 아닌 단일 값으로 취급해 증거 파일 기록 단계가 실패했습니다.
이 실패는 이력 변경 뒤 검증 출력 단계에서 발생했으며, 원격 이력은 즉시 별도 CLI로
기준선 1개임을 확인했습니다.

이후 모든 원격 이력 반환값을 명시적으로 배열화하고, Supabase CLI의 실제 JSON
응답 형태를 사용하는 회귀시험을 추가했습니다. `plan`, `apply`, `restore-legacy`,
확인문구 거부, 짧은 로그인 역할의 5개 시험이 모두 통과했습니다. 고친 도구로
운영 상태를 다시 읽고 멱등 `apply`를 실행해 `baseline → baseline`, 변경 0을 별도
암호화 증거로 남겼습니다.

`restore-legacy`는 운영 DB를 불필요하게 다시 흔들지 않도록 실운영 왕복 실행 대신,
고정된 89개 snapshot을 사용한 회귀시험으로 정확한 복원과 재적용을 검증했습니다.
실제 복귀가 필요하면 동일한 고정 해시와 정확한 확인문구가 없을 때 도구가 거부합니다.

## 판정

운영 4의 핵심 조건인 89개 이력 일치, 기준선 SQL 미실행, 전후 스키마·일반 데이터
불변, 기준선 1개 상태, 복구 명령 검증을 충족했습니다. 운영 4는 완료로 기록하며,
다음 운영 DB 변경은 기준선 뒤의 승인된 Expand 마이그레이션만 표시되어야 합니다.
