# 운영 3 준비 — 음성 별칭의 외부 자료 조회 제한

2026-09-03 13:01 KST 현재 Staging에 반영·검증됐으며 운영에는 미반영이다. 음성 폐기는 계속 `redirect`이며 분류·폐기 판정·DB 권한·새 마이그레이션은 변경하지 않는다.

## 확인한 문제

`functions/api/voice/_reagentAliases.ts`의 선택적 PubChem·KOSHA 조회에는 종료시간이 없었다. 응답을 `json()`·`text()`로 전부 읽었고, KOSHA 네트워크 오류는 이미 찾은 재고의 답변 경로까지 실패시킬 수 있었다. 이는 코드 검토에서 확인한 취약한 실패 처리이며 운영 장애가 관찰됐다는 뜻은 아니다.

## 보완 범위

- 외부 HTTP 요청마다 5초. 연결·헤더·본문을 하나의 종료시간으로 제한하며, 헤더가 늦게 와도 본문에 새 5초를 부여하지 않는다.
- 응답 최대 256 KiB. 크기 헤더를 먼저 확인하고, 누락되거나 실제보다 작아도 실제 읽은 바이트 수로 제한한다.
- 작은 조각마다 배열 항목을 계속 늘리는 대신 최대 크기가 정해진 버퍼를 사용한다.
- 외부 조회 자동 재시도 0회, redirect 거부. KOSHA 키가 다른 redirect 대상에 전달되지 않게 한다.
- 시간 초과·취소 시 정리를 요청하되 끝나지 않는 취소 후크를 기다리며 응답을 붙잡지 않는다.
- 외부 응답의 JSON 구조·CID·별칭 문자열 형식을 검사한다. 잘못된 자료를 후속 요청 주소로 사용하지 않는다.
- PubChem이나 KOSHA가 실패하면 기존 재고 이름·CAS로 계속 처리한다. KOSHA 한글명은 정확한 CAS 일치일 때만 사용한다.
- 로그에는 고정된 오류 종류와 `pubchem`/`kosha` 구분만 남긴다. 원문 오류·검색어·응답 본문·키가 포함된 URL은 기록하지 않는다.

한 별칭 생성에서 PubChem 2회와 KOSHA 1회가 순서대로 실행될 수 있다. 따라서 **음성 전체 응답이 5초 이내라는 뜻은 아니다**. OpenAI의 기존 종료시간·재시도 상한과 다른 DB 요청은 별도다. 서버가 이미 수신한 외부 요청 자체가 반드시 취소됐다고도 주장하지 않는다.

응답 전체를 제한 없이 메모리에 읽지 않는 기준은 [Cloudflare Workers 권장 사항](https://developers.cloudflare.com/workers/best-practices/workers-best-practices/)에 맞췄다. 플랫폼 타입은 `@cloudflare/workers-types` 5.20260903.1을 별도 임시 폴더에서 확인했으며 프로젝트 의존성은 변경하지 않았다.

## 검증

재고 이름 유지, 정상 별칭, 정확한 CAS, 헤더 지연, 본문 지연, 끝나지 않는 취소, 공통 종료시간, 과대 크기 헤더, 크기 헤더 누락·허위값, 재시도 없음, 잘못된 JSON·UTF-8·CID와 오류 원문 비출력을 자동시험한다. 새 모듈과 시험은 별도 strict TypeScript 검사 대상이다.
