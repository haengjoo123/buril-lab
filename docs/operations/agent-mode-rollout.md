# 검색창 에이전트 모드 출시 절차

상태: 1단계(틀과 기본 조회)와 2단계(안전·규제 현황과 재고 목록) 구현, 미배포. 빌드 플래그와 런타임 스위치 모두 꺼짐.

플래그: `VITE_ENABLE_AGENT_MODE` (기본 꺼짐)
런타임 스위치: 환경별 `BURILLAB_RUNTIME_CONFIG` KV의 **별도 키** `agent_mode_config` (없으면 꺼짐)
DB: 1·2단계는 변경 없음

## 기능

메인 검색창에 `검색 | 에이전트` 전환이 생긴다. 검색 모드는 지금과 같다.

에이전트 모드가 처리하는 요청:

| 요청 | 예 | 필요한 조건 |
|---|---|---|
| 시약 하나의 위치·잔량·유효기한 | "아세톤 어디 있어?" | 없음 |
| 만료·임박 시약 목록 | "유효기한 지난 시약 보여줘" | 없음 |
| 화면 열기 (재고, 시약장, 관리자, 일상점검, 구매 요청) | "재고 화면 열어줘" | 화면별 플래그·권한 |
| 부족해 보이는 시약 | "곧 떨어질 시약 알려줘" | `VITE_ENABLE_PURCHASE_REQUESTS` |
| 화학물질관리법 규제 대상과 지켜야 할 일 | "규제 대상 시약 알려줘" | `VITE_ENABLE_REGULATION_BATCH` |
| 잠금 확인이 필요한 시약장 | "잠금 필요한 시약장 있어?" | `VITE_ENABLE_CABINET_LOCK_RULES`, 연구실 |
| 일상점검 누락 | "점검 빠진 날 있어?" | `VITE_ENABLE_DAILY_INSPECTION`, 연구실 |
| 구매 요청 현황 | "구매 요청 현황 알려줘" | `VITE_ENABLE_PURCHASE_REQUESTS`, 연구실 |
| 이번 주 확인할 일 | "이번 주 할 일 알려줘" | 연구실 관리자 |
| 폐액통 현황 (AI 없이 규칙으로) | "폐액통 현황 알려줘" | `VITE_ENABLE_WASTE_CONTAINERS` |
| 기간별 폐기 기록 요약 (AI 없이 규칙으로) | "지난달 폐기 기록 요약해줘" | 없음 |

- 물질 정보 질문은 일반 검색으로 넘긴다.
- 앱은 조건이 맞는 기능만 서버에 알린다. 조건이 안 맞는 기능은 AI가 고를 수 없고, 앱도 실행 직전에 조건을 다시 확인한다.
- "이번 주 확인할 일"은 관리자 화면과 같은 함수·같은 문구로 만든다. 숨겨 둔 일은 빼고 건수만 알려 준다.
- 일상점검은 빠진 날짜만 알려 준다. 점검 항목의 답을 채우거나 제안하지 않는다.
- 규제 대상 목록은 CAS가 없는 품목 수와 아직 조회되지 않은 수를 함께 보여 준다. "규제 대상 아님"으로 읽히지 않게 하기 위해서다.

검색 모드에서 문장을 입력하면 "에이전트에게 묻기"를 제안만 하고, 스스로 전환하지 않는다.

## 지키는 규칙

- **AI는 "어떤 기능 + 어떤 조건"만 고른다.** 서버(`/api/agent/query`)는 연구실 데이터를 읽지 않고 아무것도 저장하지 않는다. 조회와 계산은 앱이 로그인한 사용자의 권한으로 한다.
- **응답에 자유 문장 칸이 없다.** 화면의 수치와 이름은 모두 연구실 데이터에서 그린다.
- **폐기·혼합·희석·중화·배수·폐액통 문구는 AI에 보내지 않는다.** 앱과 서버가 각각 걸러 낸다. 판별식은 음성 엔드포인트의 규칙(`DISPOSAL_SAFETY_PATTERNS`)과 같다. 음성 규칙이 바뀌어 둘이 어긋나면 `src/features/agent/agentGuard.test.ts`가 실패한다.
  - 기록을 묻는 문장(폐액통 현황, 기간별 폐기 기록)은 앱이 정해진 문구 패턴으로 알아보고 연구실 기록에서 답한다. 서버를 부르지 않는다.
  - 버리는 방법을 묻거나 무언가를 해 달라는 문장("어떻게", "부어도", "수거 요청해줘")은 고정된 안내 카드(폐액 배치 검토 열기, 폐기 기록 보기)로 끝난다.
- **물질명·CAS·제품번호만 입력하면 AI를 부르지 않고 일반 검색으로 넘긴다.**
- **CAS 번호는 사용자가 직접 입력했고 체크섬이 맞을 때만 쓴다.** 시약 이름도 사용자가 입력한 문구에 그대로 있어야 한다.
- **요청 문장은 로그에 남기지 않는다.** 서버 로그에는 계획 종류, 모델, 토큰 수, 소요 시간만 남는다.
- **여러 품목이 일치하면 하나를 고르지 않고 모두 보여 준다.**

## 서버

- 호출 제한: 사용자당 분당 6회(`AGENT` 구간), 하루 `dailyQuota`회. 제한 서비스가 응답하지 않으면 요청을 거부한다.
- AI 호출: 요청당 1회, 출력 500토큰, 제한 시간 8초, 재시도 1회. 모델은 `OPENAI_RESPONSES_MODEL`을 따르고, `OPENAI_AGENT_MODEL`로 따로 지정할 수 있다.
- 폐기 문구와 단순 물질명은 하루 횟수를 쓰지 않는다.

## 켜는 순서

1. 개인정보처리방침을 고친다. OpenAI 항목에 "에이전트 모드에 입력한 문장의 해석"을 더하고 최종 수정일을 바꾼다. `src/components/PrivacyPolicyView.test.tsx`의 날짜도 함께 고친다. 측정 단계(실패한 질의 원문 저장)를 같이 내보낼 때는 그 내용도 한 번에 넣는다.
2. Staging KV에 스위치를 넣는다. 기존 `runtime_config`와 `ai_decisions_config`는 건드리지 않는다.

   ```json
   { "mode": "read_only", "dailyQuota": 100 }
   ```

   `mode`는 `off`, `read_only`, `actions` 중 하나다. `dailyQuota`는 1~1000이다. `expiresAt`(ISO 시각)을 넣으면 그 시각 뒤에 꺼진다. 형식이 틀리거나 모르는 칸이 있으면 꺼진 것으로 본다.
3. Staging 플래그 `VITE_ENABLE_AGENT_MODE`를 `true`로 켜고 배포한다.
4. "확인할 것"을 Staging에서 확인한다.
5. 운영 KV에 같은 값을 넣고, 운영 플래그를 같은 값으로 켠 뒤 운영 배포를 한다(운영 승격은 Staging과 플래그가 같아야 통과한다).

## 끄는 방법

- 빠른 차단: KV의 `mode`를 `off`로 바꾸거나 키를 지운다. 전환 버튼은 남지만 요청하면 "아직 켜져 있지 않아요"가 나온다.
- 완전히 숨김: 플래그를 `false`로 바꿔 다시 배포한다. 검색 화면이 이전과 같아진다.

## 확인할 것

- 플래그를 끈 빌드에서 검색 화면에 전환 버튼과 제안 줄이 없는지.
- 로그인하지 않고 에이전트를 누르면 로그인으로 가고, 로그인 뒤 에이전트 모드로 돌아오는지.
- 실제 OpenAI 응답으로 `scripts`의 고정 문장 세트를 돌려 계획 정확도를 확인한다(세트는 다음 단계에서 추가). 로컬에는 OpenAI 키가 없어 1단계의 AI 경로는 모킹한 응답으로만 검증했다.
- 폐기 문구("아세톤 어떻게 버려?", "폐액통 수거 요청해줘")가 고정 카드로 끝나고 Cloudflare 로그에 `route: guard`로 남는지.
- 다른 연구실로 바꾸면 이전 결과가 지워지는지.
- 개인 공간에서 관리자 화면·일상점검·구매 요청을 열어 달라고 하면 "연구실을 선택해야" 안내가 나오는지.
- 휴대폰 폭에서 전환 버튼이 검색창 위에 놓이고 결과가 가려지지 않는지.

## 남은 일

- 3단계: 측정용 `agent_query_events`(실패한 질의만 원문 저장)
- 4단계: 기록 제안(사용량, 입고, 구매 요청, 수거 요청). KV `mode`를 `actions`로 올린다.
- 5단계: 폐액 배치 한 문장 구성(AI 없이 규칙으로 분리)
- 알려진 한계
  - "처리해", "mix" 같은 단어가 들어가면 폐기와 무관한 문장("PCR master mix 어디 있어?")도 폐기 안내 카드로 간다. 규칙을 유지하기로 한 결과다.
  - 시약장에 놓인 재고 품목 중 재고 표에서 온 줄은 시약장을 열 때 병을 강조하지 못한다.
  - 조건이 안 맞아 닫힌 기능을 물으면(예: 관리자가 아닌데 "할 일 알려줘") 이유 없이 "아직 처리하지 못하는 요청"으로만 나온다.
  - 폐기 기록 요약은 한 번에 최근 1,000건까지만 합친다. 넘으면 카드에 표시한다.
  - 폐기 기록을 "뭐 버렸어?"처럼 물으면 기록 질문으로 알아보지 못하고 고정 안내 카드로 간다.
