# 화관법·연구실안전법 연계 기능 롤아웃

이 기능은 다섯 PR로 나눠 들어간다. 각 PR은 기본 꺼짐 플래그 뒤에 있다. 법령 근거는 `docs/operations/regulation-obligations-sources.md`에 있다.

## 1. 규제 카드 "할 일" 개편 (`VITE_ENABLE_REGULATION_ACTIONS`)

- DB 변경 없음.
- 재고 상세와 검색 결과의 화관법 카드가 할 일 1~4줄을 먼저 보여 준다. 분류명·농도 기준·예외·고시일·근거 법령은 "분류 근거 보기" 안에 접혀 있다.
- 같은 PR에서 일상점검 문구 6개를 고시 원문에 맞췄다(`kr-daily-v2`). 이 변경은 플래그와 관계없이 바로 적용된다.
- 켜기: Staging과 운영 변수를 함께 `true`로 바꾸고 배포한다.

## 2. 분류 저장·일괄 조회·목록 필터 (`VITE_ENABLE_REGULATION_BATCH`)

- **DB:** `20261116090000_regulation_source_cache`는 `chemical_source_cache`의 CHECK 제약만 넓힌다(source `keco`, record_type `regulation`). 이 테이블은 service role만 접근한다.
- **서버**
  - `GET /api/chemicals/regulations`(기존): 엣지 캐시 → DB 캐시 → KECO 순서로 찾고, 확정 답은 DB에 저장한다. 저장 기간은 찾음 30일, 없음 7일이다. DB 캐시가 없어도 예전처럼 동작한다.
  - `POST /api/chemicals/regulations-batch`(신규, 로그인 필수): 한 번에 CAS 100개까지 받는다. DB 캐시와 엣지 캐시에서 먼저 답하고, 나머지는 요청당 12개까지만 KECO에 묻는다. 그 이상은 `pending`으로 돌려준다.
  - 클라이언트는 2.5초 간격으로 최대 12번 다시 묻는다.
- **화면**
  - 재고의 기존 "위험 분류" 드롭다운에 "화관법 규제물질" 항목 1개가 추가된다. 허가·제한·금지·유해화학물질이 대상이다.
  - 위험분석용 목록 엑셀에 "화관법 분류" 열과 안내 문구가 추가된다. 카드에는 칩을 추가하지 않는다.
- **순서**
  1. Staging과 운영에 migration을 연달아 적용한다. Staging만 먼저 적용하면 main의 hosted 보안 검사가 실패한다.
  2. 운영 승격 전에 `WEB_DATABASE_REVIEWED_SHA`를 해당 커밋으로 갱신한다.
  3. 두 환경의 플래그를 함께 켠다.
  - migration 전에 플래그를 켜도 화면은 깨지지 않는다. 다만 DB 저장이 실패해 매번 KECO를 부르게 되고, 경고 로그가 남는다.
- **KECO 쿼터:** 처음에는 연구실의 모든 CAS를 KECO에서 한 번씩 조회한다. 답은 연구실·사용자와 관계없이 CAS 단위로 공유되므로, 이후 다른 연구실은 대부분 DB 캐시에서 답을 받는다.

## 3. 시약장 잠금·보관 경고 (`VITE_ENABLE_CABINET_LOCK_RULES`)

- **DB:** `20261116100000_cabinet_locked`는 `cabinets.locked boolean` 열만 추가한다. `null`은 미설정, `true`는 있음, `false`는 없음이다.
  - 기존 시약장은 `null`로 남는다.
  - 표 단위 권한과 수정 정책이 그대로 적용된다.
  - `get_cabinet_state_v2`는 `to_jsonb(c)`로 새 열을 그대로 돌려준다.
- **화면**
  - 시약장 편집 폼에 "잠금장치 있음 / 없음 / 모름" 한 줄이 추가된다. 새로 만들 때 고른 값은 생성 직후 저장된다.
  - 카드에는 잠금장치가 있을 때만 자물쇠 아이콘이 붙는다.
  - **경고는 "없음"으로 기록된 시약장에만 나온다.** 대상은 그 안의 독성 물질(신뢰 GHS 그룹: 급성독성·시안화물·황화물·아자이드), 발암성 1군(H350), 화관법상 잠금 보관 대상이다. 화관법 대상 판정은 `VITE_ENABLE_REGULATION_BATCH`가 켜져 있을 때만 한다.
  - 경고가 나오는 곳은 모두 기존 자리다:
    - 3D 보관 경고 배너의 단일 물질 행("◯◯ · 잠금 없는 시약장");
    - 병 테두리;
    - 시약 편집 패널의 보관 호환성 섹션;
    - 재고 상세 "보관 위치" 카드의 한 줄.
  - 배너의 자동 배치 버튼은 위치를 옮겨 해결되는 문제가 있을 때만 보인다.
  - 저장이나 배치를 막지 않는다.
- **순서:** 2번과 같다(migration을 두 환경에 연달아 적용 → `WEB_DATABASE_REVIEWED_SHA` 갱신 → 플래그). migration 전에 켜면 잠금 선택값 저장이 실패한다.
- **관리자 할 일로 이동한 것:** "잠금 여부를 정하지 않은 시약장" 알림은 일상점검 신호와 함께 4번에서 다룬다.

## 4. 일상점검 힌트·관리자 할 일 (`VITE_ENABLE_INSPECTION_HINTS`)

- DB 변경이 없다. 1~3번의 데이터를 읽기만 한다.
- **일상점검 힌트**(`VITE_ENABLE_DAILY_INSPECTION`도 켜져 있어야 함): 연구실 기록이 말해 줄 수 있는 항목 밑에만 한 줄이 붙고, 답은 자동으로 고르지 않는다.
  - `chemical_toxic`: 잠금장치 없는 시약장의 독성·발암성 물질 수. 그런 시약장이 없으면, 독성 물질이 있는데 잠금 여부가 미설정인 시약장 수를 보여 준다. 3번 플래그가 필요하다.
  - `chemical_waste`: 확인할 폐액통 수. 관리자 카드와 같은 기준(80% 이상, 봉인 14일, 수거 요청)이다.
  - "보기"를 누르면 해당 시약장이나 폐액통 목록으로 이동한다.
- **관리자 할 일**(둘 다 주 단위 숨기기 가능)
  - `daily_inspection_missing`: 오늘을 뺀 최근 7일의 평일 중 기록 없는 날이 2일 이상이면 뜬다. 주말은 세지 않는다. "점검 열기"는 `/logs?view=inspection`으로 이동한다.
  - `cabinet_locks`: 잠금장치 없는 시약장에 독성·발암성 물질이 있으면 그 내용을, 없으면 잠금 여부 미설정 시약장을 알린다. 3번 플래그가 필요하다.
- **관리자 현황:** 2번 플래그도 켜져 있으면 "시약" 타일에 "화관법 규제물질 N종 · 정밀안전진단 대상(2년마다)" 한 줄이 붙는다. 근거는 연구실안전법 시행령 제11조제2항제1호·제3항이다.
- **넣지 않은 힌트**
  - MSDS 비치: 종이 비치를 앱이 알 수 없어 오탐이 많다.
  - 성상별 보관: 연구실 전체 시약장 배치를 읽어야 해 비용이 크다. 시약장 화면의 기존 보관 경고로 충분하다.
