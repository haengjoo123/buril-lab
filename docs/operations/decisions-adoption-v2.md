# Decisions 채택률 개선과 재평가

정책 v2는 선택 확률 0.90, 차순위 차이 0.20을 유지한다. 모델·SDK·기존 Responses 질문, 규칙 엔진과 최종 검토 절차는 변경하지 않는다.

- 음성: 잔량·만료일·위치 질문의 대상 시약만 식별한다. 후보 이름·CAS·브랜드·제품번호·표시된 보관 위치를 선택지에 연결하고, 질의에 실제 구분 근거가 있을 때만 여러 병을 구분한다. 같은 정보의 병, 이름만으로 여러 병이 일치하는 경우, 알 수 없는 대상은 계속 보류한다.
- 보조 분류: 기존 10개 값과 우선순위를 보존한다. 순수한 물의 NEUTRAL 의미, 누락된 선택 정보와 실제 충돌의 차이, 미확인 혼합물의 UNKNOWN 조건을 명확히 한다. 이는 폐기·보관 승인이나 내용물 검증이 아니다.
- 메타데이터·캐시 키 정책을 v2로 분리한다. v1 요청 질문은 원본 SHA-256 회귀 검사로 고정해 서버 평가에서만 재사용한다.

## 비교 경로

평가 backend에 `decisionsV1`을 추가했다. `legacy`는 원래 Responses, `decisionsV1`은 변경 전 Decisions 질문, `decisions`는 v2 질문이다. 세 경로 모두 같은 고정 입력과 운영 서버 key/HMAC을 사용하며 5초 제한·재시도 없음, 캐시/DB/별칭 쓰기 없음이다. 기존 환경별 공개키 grant, canonical 운영 host, 15초 서명·1시간 이하 grant 검증을 유지한다.

평가 결과는 정책 버전, 제안 선택, 채택/보류 이유, 선택 확률·분포·별도 confidence를 보존한다. 일반 로그에 발화·재고 원문을 추가하지 않는다.

원래 400개 합성 변형을 변경하지 않고, API 호출 전 별도 고정한 80개 계약 검증 사례를 추가했다. 새 사례는 명시된 브랜드·제품번호·위치, 복수 병 모호성, 후보 120개/상한 밖 후보, 미확인 대상, 이름·CAS·분자식 충돌, 미확인 혼합물, 프롬프트 삽입을 포함한다. 기능별 40개이며 사람이 검토한 독립 안전 정답셋으로 표시하지 않는다.

CLI의 `--prepare <OS-임시-디렉터리> --environment production --all`은 전체 480개 사례를 허용하는 공개 grant를 만든다. 운영 KV에 해당 공개 grant만 임시 등록한 뒤 `--state <개인-상태-경로> --output <보고서.json> --compare-v1 --wait-grant`로 세 경로를 비교한다. `--guards`는 추가 사례 80개만 선택한다. grant 최대 사례 수는 등록된 고정 pool에 맞춘 480개다. 기존 CI workflow는 staging 전용으로 유지한다.

기존 400건의 `summary`와 추가 검증 사례의 `guardSummary`를 별도로 기록한다. 평가 도중 질문·정답을 바꾸지 않는다. 전송 실패 시 원본을 보존하고 명시적 `--resume`만 사용하며, 비교 backend 구성이 달라진 보고서는 이어하지 않는다. 종료 후 현재 grant ID 대조·삭제, signed probe 거부·미인증 404, 로컬 임시 개인키 제거를 확인한다.

## 판정 한계와 운영 상태

원래 음성 200건에서 선택이 정답인 사례는 90건이다. 이전 Responses의 103개 채택에는 오선택 13개가 포함됐다. 이 집합에서 채택 정확도 100%를 유지할 경우 최대 올바른 채택은 90건으로, 원래 `기존 채택의 90% 이상` 기준(최소 93건)을 동시에 만족시킬 수 없다. 이 사실을 숨기거나 기준을 완화하지 않는다. 기존 대비 채택 수와 정답을 선택할 수 있는 사례의 채택 수를 함께 기록한다.

실제 사용자 shadow 24시간/100건, 독립 안전 정답셋 및 후속 관찰은 이 합성 재평가와 별개다. 기존 운영 shadow 10%를 유지하며 이번 변경으로 active 전환하지 않는다.
