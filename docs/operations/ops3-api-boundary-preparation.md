2026-09-03 KST. **운영 미반영**입니다. PR #66의 첫 Staging 배포 실패 후 PR #67·#68을 반영한 SHA `a703570f2e4cc6ad773b051f583ec04c060caaf0`의 run `33694980335`는 일반·고정 Staging 주소의 Gate0 및 CSP 검사를 통과했습니다. [최신 성공·정리 증거](ops3-staging-success-2026-09-03.md)와 [이전 실패 증거](ops3-staging-evidence-2026-09-03.md)를 분리합니다. 실제 OpenAI·사진 업로드의 새 경계 검증과 운영 사진 백업의 일일 2회·관찰은 여전히 별도입니다.

## 구현 범위

- 알려진 API 경로와 메서드를 명시하여 JSON 404/405를 반환합니다. 존재하지 않는 API가 SPA 화면으로 떨어지지 않게 합니다.
- 운영 CORS는 정식 도메인과 네이티브 앱만 허용합니다. Staging 및 로컬 주소는 각각의 환경에서만 허용합니다.
- 저장소의 네이티브 설정(`app.buril-lab.local`, Android `https`, iOS 기본 `capacitor`)에 맞는 정확한 두 앱 주소만 허용합니다. 비슷한 외부 주소·다른 네이티브 호스트·HTTP는 거부합니다. iOS 기본 주소 체계는 [Capacitor 공식 설정 문서](https://capacitorjs.com/docs/config)와 설치된 CLI 선언에서 확인했으며, 이 API 호환 검사는 앱스토어 출시나 실제 iOS 기기 시험을 뜻하지 않습니다.
- 민감 응답에 캐시 금지, 콘텐츠 형식 오인 방지, referrer 제한, 서버가 생성한 요청 ID를 적용합니다. 정적 `_headers`와 Functions 헤더는 분리합니다.
- 운영 HSTS는 1일만 적용하며 하위 도메인 전체 적용과 preload는 넣지 않습니다.
- 웹의 런타임 설정 판독기도 `storage_backup_enabled`를 포함한 다섯 필드를 모두 검사합니다. 백업 필드가 없거나 Boolean이 아니면 KOSHA도 `link_only`로 제한합니다. 실제 백업 실행은 전용 Worker만 담당하며 웹에서 켜지 않습니다. KV 읽기 실패 로그에는 내부 오류 원문을 남기지 않습니다.
- 관리자 API는 별도 요청 제한을 사용합니다. 제한 장치의 오류와 `success: true` 형태로 오는 timeout도 민감·유료 API에서 거부합니다.
- 관리자 상태 변경·서명 URL·내보내기의 UUID, 요청 형식, 감사 실패, 일반화된 오류 응답을 보강합니다. 목록 조회가 DB를 갱신하는 호출은 제거합니다.
- 업로드/JSON은 크기 헤더를 먼저 검사하고, 헤더가 없거나 실제보다 작은 경우에도 읽은 바이트 수로 제한합니다. 느린 본문 읽기는 10초에 중단합니다. 작은 조각이 많이 와도 조각 배열을 무제한 보관하지 않습니다.
- 본문 취소를 요청한 뒤 연결 정리가 끝날 때까지 무제한 기다리지 않습니다. 종료되지 않는 `cancel()`을 모의한 시험에서 기존 대기 문제를 재현한 뒤, 제한 시간이 유지되도록 수정했습니다. 운영 장애가 관찰됐다는 뜻은 아닙니다.
- 음성 전사 파일은 5 MiB까지 허용합니다. 기존 클라이언트 녹음 시간 제한을 없애거나 서버가 녹음 길이를 검증한다고 주장하지 않습니다.
- 음성 합성·질의의 잘못된 필드와 화학정보 JSON 구문 오류는 외부 호출 전에 일반화된 400 응답으로 처리합니다.
- OpenAI 음성 호출은 요청당 30초, 자동 재시도 0회로 제한합니다. 공급자 오류 원문을 반환하지 않고 공급자 인증 오류를 사용자 로그인 오류로 전달하지 않습니다.

## 본문 상한

| 요청 | 상한 |
|---|---|
| 일반 JSON·음성 합성 | 64 KiB |
| 검색 분석 이벤트 | 32 KiB |
| 음성 질의·폐액 문맥 | 256 KiB |
| 음성 전사 multipart | 5 MiB + 부가 필드 64 KiB; 실제 파일은 별도로 5 MiB 검사 |
| 신규·레거시 라벨 분석 JSON | 12 MiB; 기존 디코딩 이미지 8 MiB 제한도 유지 |

크기 검사는 인증과 반복 요청 제한 뒤, 각 JSON/multipart 해석기 앞에서 수행합니다. 크기를 확인한 Request를 다음 함수에 넘기는 방식은 [Cloudflare Pages의 `context.next(request)` 계약](https://developers.cloudflare.com/pages/functions/api-reference/)을 사용합니다. 음성 호출의 시간·재시도 제한은 [OpenAI 공식 SDK의 명시적 옵션](https://github.com/openai/openai-node#timeouts)을 사용합니다.

## 실제 Pages 실행 환경을 사용하는 추가 시험

`npm run test:pages-boundary`는 Vite 미리보기가 아니라 고정된 Wrangler로 실제 Pages Functions를 컴파일하고, 복사한 빌드 산출물과 **수정하지 않은 `_headers`**를 loopback 주소에 띄웁니다.

- HTTP 조건 37개: API 루트·미등록 경로 JSON 404, 메서드 405, 신규·레거시 AI/음성/관리자 인증 거부, CORS, 보안 헤더, 반복 요청 제한 장치 미설정 시 503, 잘못된 UUID, 실제 chunked 전송 상한, 느린 본문 408
- Chromium 흐름 3개: 로그인/회원가입/공개 검색 화면, 음성 창, 가상 카메라와 합성 사진 미리보기, WebP/Blob/가상 오디오/Worker 자원, 금지된 인라인·외부 스크립트의 실제 CSP 차단
- 일반 흐름에서 CSP 위반 0. 차단 시험에서는 의도한 위반을 반드시 검출하며 스크립트가 실행되지 않는지 확인
- 공급자 키·원격 DB·원격 바인딩 0. 실행 자식 프로세스에는 키나 프록시 환경을 전달하지 않고, hosted Supabase 주소가 들어간 브라우저 빌드는 거부
- 카메라·마이크는 Chromium 가상 장치만 사용. 파일은 미리보기까지만 확인하고, DB/Storage 업로드나 OCR/유료 AI를 실행하지 않음
- 시험이 끝나면 해당 프로세스와 해당 임시 실행 폴더만 정리. 사용자가 실행 중인 다른 서버는 재사용하지 않음

로컬 Node→workerd HTTP 연결은 업로드가 끝날 때까지 응답 전달을 보류할 수 있습니다. 따라서 느린 업로드 시험은 앱의 제한 시간 이후 스트림을 종료한 뒤 408인지 확인합니다. 본문을 읽기 전 상한 검사와 취소 정리가 제한 시간을 늘리지 않는지는 별도 단위시험으로 확인합니다. 이 결과를 운영의 모든 미완성 연결이 정확히 10초에 닫힌다는 증거로 사용하지 않습니다.

CI의 기존 Gate 0 화면·빈 DB 시험은 유지합니다. 배포 범위 검사는 `verify-ops3-release-scope.mjs`로 명시적으로 전환하여 고정된 이전 main 이후 **이번 API·시험 파일만** 허용합니다. 가입·삭제 Worker·새 마이그레이션·의존성 변경은 거부하며, 이전 Gate 0 범위 검사기는 그대로 보존합니다. 이 전환은 주간 운영 배포나 관찰 기간을 승인하는 장치가 아닙니다.
