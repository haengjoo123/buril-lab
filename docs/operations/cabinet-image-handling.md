# 시약장 사진의 저장 전 변환

기준 시각: 2026-08-26 KST

이 문서는 새로 올리는 **시약장 사진**의 용량과 개인정보 노출을 줄이는 현재 앱 동작을 설명합니다. `media-products` 등 다른 Storage 버킷에는 적용하지 않습니다.

## 현재 적용 범위

- 사용자가 고른 JPEG, PNG, WebP 사진만 받습니다. 파일의 확장자뿐 아니라 앞부분 형식도 함께 확인합니다.
- 원본은 최대 20 MiB, 해상도는 최대 6,400만 화소로 제한합니다.
- 사진은 브라우저 안에서 긴 변을 최대 1,920px로 줄이고 WebP로 다시 저장합니다. 2 MiB 이하가 될 때까지 품질과 크기를 단계적으로 낮춥니다.
- Canvas로 다시 저장하므로 일반 사진의 EXIF·GPS 같은 촬영 메타데이터는 저장본에 남지 않습니다.
- Storage에는 변환된 WebP 한 장만 올립니다. 원본 바이트는 서버나 Storage로 전송하지 않습니다.
- 파일 경로는 매번 새 UUID를 사용합니다. 그래서 1년 캐시를 써도 이전 사진이 새 사진으로 잘못 보이지 않습니다.
- DB 연결이 실패하면 방금 올린 새 WebP만 지워서 연결되지 않은 파일을 만들지 않습니다. 기존에 연결된 사진은 그대로 둡니다.

이 값은 사진 속 라벨·시약장 상태를 보기에는 충분한 크기를 유지하면서, 장기 보관과 매일 복구 사본의 크기를 예측 가능하게 만들기 위한 기준입니다. 사진 1장이 항상 2 MiB가 되는 것은 아니며, 더 작은 사진은 더 작게 저장됩니다.

## 아직 하지 않은 일과 금지 사항

- 이 변경만으로 Storage 버킷이 비공개가 되지는 않습니다. 현재의 `image_url` 공개 경로와 브라우저 직접 업로드 구조는 **사진 Switch 관문**에서 `image_path`, 짧은 열람 주소, 서버 측 소유권 검사로 바꿉니다.
- 따라서 이번 클라이언트 검사는 보안 경계가 아닙니다. Switch 전에도 버킷의 서버 측 파일 크기·MIME 제한을 별도로 설정·검증해야 합니다.
- 기존 사진은 이번 변경으로 변환·이동·삭제하지 않습니다.
- 기존 공개 사진을 비공개 경로로 옮기는 작업은 전송 뒤 크기와 SHA-256을 확인하고, 원본을 7일 보존한 다음 별도 승인으로만 삭제합니다.
- 사진을 교체해도 현재 연결돼 있던 이전 객체를 바로 지우지 않습니다. 비공개 전환과 검증된 정리 대기열이 완성되기 전에는 이전 공개 주소를 임의로 끊지 않기 위해서입니다. 따라서 운영 R2 백업을 켜기 전에는 남은 연결 없는 객체를 별도 점검·승인 절차로 정리해야 합니다.
- R2 복구 Worker는 계속 OFF입니다. 이 변경이 Worker 활성화나 운영 배포 승인을 뜻하지 않습니다.

## Staging 확인 기준

- 가로·세로 사진 각각에서 저장본이 WebP이고 긴 변이 1,920px 이하인지 확인합니다.
- 원본의 촬영 위치가 저장본 메타데이터에 남지 않는지 확인합니다.
- 20 MiB 초과, JPEG/PNG/WebP 이외 형식, 손상 파일, 6,400만 화소 초과 파일이 업로드 전에 거부되는지 확인합니다.
- DB 연결 실패 때 새 Storage 객체가 제거되고, 이전에 연결된 사진이 유지되는지 확인합니다.
- 실제 사용자 사진이 아닌 합성 사진으로 Storage 백업·복원 시험을 합니다.

운영 배포 전에는 이 문서의 기준을 현재 Storage 정책과 별도로 대조합니다. 사진 비공개 전환, 기존 사진 이관, 원본 정리는 이번 변경과 같은 배포에 섞지 않습니다.
